## Устройство

- `internal/vpnkey` — декодирование `vpn://` (base64url, длина, zlib, JSON).
- `internal/keyapi` — `client-api/v1`, API провайдера за ключом `vpn://`: `get-request`, `download-awg-key`, страны, `check-change-server`/`change-server`. Заголовок `X-Device-Id` — собственный случайный ID AWG Pilot. Данные других VPN-приложений программа не читает.
- `internal/remotecfg` — публичный конфиг провайдера (`api_base_url`, типы подключений).
- `internal/routing` — вычисление AllowedIPs для раздельного туннеля.
- `internal/tunnel` — `amneziawg-go` v3 (AmneziaWG 3.1, совместим с 2.0), wintun, маршруты, DNS и WFP из `amneziawg-windows` v0.2.0. Ключи AmneziaWG 3.x, которых не знает парсер `amneziawg-windows`, передаются в устройство отдельно (`internal/awgconf`).
- `internal/store` — настройки в `%APPDATA%\AWGPilot\settings.json`, секреты в `secrets.bin` (DPAPI).
- `internal/wfp` — правила «программа только через VPN». Низкоуровневые типы и вызовы WFP скопированы из `amneziawg-windows/tunnel/firewall` (MIT, © WireGuard LLC).
- `internal/tray` — иконка в трее (`fyne.io/systray` в отдельном потоке ОС).
- `internal/autostart` — пункт «Автозагрузки» текущего пользователя (`HKCU\...\Run`).
- `internal/service` — служба Windows «AWG Pilot VPN» (LocalSystem): туннель, маршруты, kill switch, правила программ. Тот же exe с ключом `--service`.
- `internal/ipc` — канал управления `\\.\pipe\AWGPilot` между окном и службой (доступ: SYSTEM, администраторы, вошедший пользователь).
- `internal/geoip`, `internal/usage` — список российских сетей и статистика трафика.
- `internal/netx` — разрешение имён внутри процесса для запросов программы (работает и при блокировке интернета).
- `widget.go`, `frontend/src/widget.ts` — окошко статуса (`awgpilot.exe --widget`).
- UI: Wails v2 + TypeScript (`frontend/`), запускается без прав администратора.

К API провайдера приложение обращается **только по нажатию кнопки**. Параметр `force_update_device` (перепривязка ключа к ПК) отправляется только после отдельного подтверждения.

## Установка

`build\bin\awgpilot-amd64-installer.exe` ставит программу в `C:\Program Files\AWG Pilot`, регистрирует и запускает службу «AWG Pilot VPN» и создаёт ярлыки в меню «Пуск» и на рабочем столе. Права администратора нужны только установщику. Если AWG Pilot запущен, установщик его закроет (VPN на секунду отключится). Удаление — через «Параметры → Приложения». При удалении установщик спросит, удалять ли сохранённый ключ и настройки.

Автовосстановление работает ступенями, пока сервер не отвечает (3 минуты без рукопожатия или 30 секунд без ответа на пинг через туннель):
1. переподключение;
2. свежий конфиг у провайдера (туннель на это время опускается, чтобы запрос не ушёл в неработающий сервер) и переподключение;
3. переключение на следующий профиль (другой ключ или `.conf`), и всё сначала уже на нём;
4. другой сервер: автоматически, если включена соответствующая галочка, иначе баннер и уведомление с кнопкой «Запросить другой сервер» (лимит провайдера — раз в сутки);
5. дальше — повторные переподключения.

**Отключать интернет при обрыве VPN** (Настройки → Защита). Если VPN упал не по команде пользователя, служба закрывает интернет мимо VPN фильтрами WFP (`internal/wfp/lockdown.go`) и держит его закрытым, пока VPN не восстановится или пока пользователь не нажмёт «Отключить» / «Разблокировать интернет». Флаг `%ProgramData%\AWGPilot\lockdown` сохраняет блокировку при перезапуске службы. Пока интернет закрыт, программа пробует подключиться каждые 30 секунд, перебирая профили. Её собственные запросы проходят: фильтр пропускает AWG Pilot, а имена она разрешает сама (`internal/netx`), потому что системная служба DNS тоже попадает под блокировку.

**Окошко статуса** (меню трея или Настройки → Запуск) — тот же exe с ключом `--widget`: маленькое окно поверх других без кнопки на панели задач. Зелёное — VPN работает (пинг, скорость), красное — связь прервана или интернет заблокирован, серое — VPN выключен. Данные берёт напрямую у службы, место на экране запоминает; двойной щелчок открывает программу.

## Сборка

```powershell
$env:PATH="D:\CLAUDE_CODE\tools\go\bin;D:\CLAUDE_CODE\tools\gopath\bin;$env:PATH"
$env:GOPATH="D:\CLAUDE_CODE\tools\gopath"; $env:GOTOOLCHAIN="local"
wails build -platform windows/amd64 -trimpath -ldflags "-s -w"
go test ./...
```

С установщиком (нужен NSIS, портативный 3.13 лежит в `D:\CLAUDE_CODE\tools\nsis-3.13`, добавьте его в PATH): `wails build ... -nsis`. `project.nsi` должен оставаться в UTF-8 с BOM, иначе русский текст установщика испортится. Иконку пересоздаёт `go run ./cmd/genicon build/appicon.png` (затем удалите `build\windows\icon.ico`, Wails соберёт его заново).

Результат: `build\bin\awgpilot.exe`. Для работы туннеля нужна установленная служба (через установщик); для разработки служба запускается в консоли администратора командой `awgpilot.exe --service-console`. Рядом должен лежать `wintun.dll` 0.14.1 (wintun.net, SHA-256 архива `07c25618…ef51`, подпись WireGuard LLC).

Офлайн-проверка настоящего конфига и ключа (значения не печатаются):

```powershell
$env:AWGPILOT_REAL_CONF="<экспортированный из AWG Pilot .conf>"
$env:AWGPILOT_REAL_KEY_FILE="<файл с vpn://-ключом>"
go test ./internal/tunnel ./internal/vpnkey -v -run Real
```

## Первый запуск

1. Отключите VPN в другом клиенте с тем же ключом: два клиента с одним ключом мешают друг другу.
2. Установите AWG Pilot установщиком и запустите с ярлыка (без запроса UAC).
3. «Профили и ключи» → вставьте свой `vpn://`-ключ → «Добавить ключ».
4. «Подключение» → «Обновить конфиг» → кнопка питания. Проверьте IP на любом сайте вроде 2ip.ru.
5. IPv6: на test-ipv6.com должно быть «IPv6 не обнаружен», а IPv4-адрес — от VPN.
6. Добавьте программу в «Программы только через VPN», сохраните, отключите VPN: у программы не должно быть сети. Подключите — сеть вернётся.
7. Закройте окно: программа уйдёт в трей. Значок зелёный при подключении и серый без него.
8. «Профили и ключи» → «Обновить статус» показывает срок оплаты и число свободных устройств.

## Что выяснилось на живом тесте (31.10.2026)

- `download-awg-key` требует заголовок `X-Supported-Awg-Version: 2.0`. Без него сервер отвечает 406 `available_wg_server_not_found`, а на `2` — 400 `invalid_awg_version`. Ответ приходит не JSON, а сам конфиг (`text/plain`).
- Выбора страны у проверенного провайдера нет (`country-list.json` → 404). Сервер назначает провайдер. Если сервер не работает, можно запросить другой (`change-server`), не чаще раза в сутки.
- Kill switch из `amneziawg-windows` рассчитан на службу Windows (служебный SID) и в обычной программе падал с `ERROR_NO_SUCH_GROUP`. Теперь он лежит в `internal/wfp` и пропускает AWG Pilot по пути к exe.
- Сокет можно привязать к физическому интерфейсу только после `dev.Up()`: такой же порядок у `amneziawg-windows`.
- После подъёма Windows около 4 секунд активирует маршруты и DNS адаптера.

Живые проверки (`cmd/livecheck`, ключи не печатает, IP маскирует):

```powershell
build\bin\livecheck.exe api -key-file <файл с ключом> [-download]
build\bin\livecheck.exe tunnel -conf <файл .conf> -log <лог>      # от администратора
```

## Android

Тот же интерфейс (`frontend/`) в WebView и то же Go-ядро, собранное как `libawgpilot.so`:

- `mobile/` — ядро для Android: профили, API провайдера, маршруты, устройство `amneziawg-go` на дескрипторе от `VpnService`, автовосстановление и пинг через туннель (ICMP-пакеты подмешиваются прямо в туннель, `pinger.go`). Связь с Java — `jni.c` и `main_android.go`.
- `internal/awgconf` — разбор конфига без зависимостей от Windows.
- `android/` — Java-оболочка: `MainActivity` (WebView, отступы под системные панели), `AwgVpnService` (интерфейс VPN, уведомление со скоростью, смена сети), `QsTile` (плитка в шторке), `Keys` (ключ шифрования `secrets.bin` под защитой Android Keystore).

Отличия от Windows:
- Само приложение всегда идёт мимо своего VPN, поэтому запросы к провайдеру работают и при «мёртвом» сервере, а сокет туннеля не нужно защищать.
- Раздельный туннель по приложениям в обе стороны: «только выбранные» и «все, кроме выбранных».
- Kill switch и «интернет без VPN» — системные: «Постоянная VPN» и «Блокировать подключения без VPN» в настройках Android (кнопка в «Настройках» приложения). Постоянная VPN подключает AWG Pilot при загрузке телефона.
- «Россия мимо VPN»: Android принимает ограниченное число маршрутов, поэтому напрямую идут крупнейшие российские сети (Android 13+: около 85 % адресов через `excludeRoute`, Android 5–12: около 64 %). Остальные российские адреса идут через VPN, утечки нет.
- Поддерживается Android 5.0+ (API 21), архитектуры arm64-v8a, armeabi-v7a, x86_64.

Сборка без Gradle (нужны Android SDK с build-tools 36.1, platform 36 и NDK 28, JDK 17+):

```powershell
.\android\build.ps1          # -> build\android\awgpilot-<версия>.apk
```

Ключ подписи создаётся один раз в `D:\CLAUDE_CODE\tools\awgpilot-signing` — сохраните эту папку: обновления ставятся поверх только с тем же ключом.

## Ограничения

- Правила для программ работают только в одну сторону: «программа только через VPN». Обратное («эта программа мимо VPN») на Windows требует драйвера WFP-callout. Пока выход такой: раздельный туннель по адресам и доменам.
- Правила для программ действуют, пока запущен AWG Pilot (динамическая сессия WFP). Поэтому сбой программы не может навсегда оставить кого-то без сети.
- Домены разрешаются в IP при подключении. У CDN адреса меняются, поэтому иногда нужно переподключиться.
- IPv6 через туннель не маршрутизируется (провайдер его не выдаёт). Галочка «Блокировать IPv6» закрывает утечку, сайты открываются по IPv4.
- Kill switch действует только в режиме «весь трафик». При автоматическом переподключении он на секунду снимается вместе с туннелем — без этого окна обходится опция «Отключать интернет при обрыве VPN».
- Если в импортированном `.conf` сервер указан именем, а не IP, при заблокированном интернете служба не сможет его разрешить (у конфигов провайдера там IP).
- Проверка подписки раз в 6 часов — единственный запрос к провайдеру без нажатия кнопки; выключается в настройках.
- Вживую проверены `get-request` и `download-awg-key`. `change-server` вызывается только по кнопке, поэтому его не трогали, чтобы не тратить суточный лимит.

## Проверка правил для программ (нужна консоль администратора)

```powershell
go test ./internal/wfp -v -run TestAppRulesBlockAndRelease
```

Тест закрывает `curl.exe` правилом «только через VPN» при выключенном туннеле, убеждается, что сеть пропала, и после снятия правил — что она вернулась.
